# Browser matrix diagnosis

Playwright binaries were downloaded to `/tmp/lawdesk-qa-pw-browsers-20261110`; Ubuntu runtime packages were unpacked to `/tmp/lawdesk-qa-browser-libs-20261110` without modifying the host. With `LD_LIBRARY_PATH` pointing to those packages, Chromium 156 launched and completed 32 read-only UAT route/locale/viewport checks on each of the three deployed SHAs; see `browser-uat-result.json`, `browser-uat-result-aea33fa.json` and `browser-uat-result-514c481.json`. A limited filter/language/keyboard check passed on `aea33fa` in `browser-uat-interactions-result.json`.

- Firefox launch remained BLOCKED: its `libxul.so` requires NSS symbols `NSS_3.101`, `NSS_3.107`, `NSS_3.113` and `NSS_3.126` absent in this host's `libnss3.so`; `libX11-xcb.so.1` is also absent. This is a browser runtime dependency error before any application page loaded.
- WebKit launch remained BLOCKED: `ldd` on `MiniBrowser` reported missing `libWPEWebKit-2.0.so.1`, `libbacktrace.so.0`, several GStreamer and Flite libraries and other components. A matching `libjxl.so.0.8` package was unavailable in the current isolated package set. The host's Docker socket denied access to this QA identity, so the official Playwright image could not be used. UAT server settings were not changed.

The `browser-probe.json` records the initial launch failure. The statements above record the later library probe. The current Chromium run found eight serious axe observations on `.wp3-bell` across cases/case, Arabic/English and phone/desktop; see QA-RT-008. Firefox and WebKit have no application PASS claim. Retest in a compatible disposable Linux image or browser executor with those runtime dependencies, then rerun the same authenticated route matrix and interaction, keyboard and network cases.
