# بوابة فهم LawDesk — Arabic interactive portal (draft, not deployed)

Separate static site that explains every **implemented** LawDesk feature in Arabic, plus the real Floorplan map of the code.
Nothing here changes LawDesk (no business logic, schema, auth, routes, R5/R6 branches or QA evidence). Not merged to develop.

## Layout
| Path | What |
|---|---|
| `content/features/*.json` | One Arabic page per feature (contract: `SCHEMA.md`); every step/rule/error has file+line evidence |
| `content/{categories,glossary}.json`, `about.html` | Sidebar categories, terms, limits page |
| `planned/{r5,r6}.json` | R5/R6: unmerged or documentation-only, with PR, SHA and QA status |
| `floorplan-src/` | `architecture.json` (generated by `tools/gen_architecture.py`), Arabic `descriptions/` (792 files, 300 routes), plugin version |
| `tools/validate_content.py` | Checks every evidence path/line range/endpoint against the repository at the build SHA |
| `tools/build_portal.py` | Static site generator (stdlib only, no network, no external fonts/scripts) |
| `tools/refresh_portal.sh` | Reproducible update for one develop SHA (see below) |
| `tests/test_portal.py`, `tests/browser_test.mjs` | Quality gates (17 unit/build tests; real-Chromium desktop + iPhone acceptance) |
| `deploy/` | Dockerfile, nginx, compose, `scripts/{deploy,verify,rollback}.sh`, `proxy/{attach,detach}.sh` |

## Floorplan plugin
Official `haydenschmitty/floorplan` v0.11.0 (upstream `94f81b4`, MIT), installed **local scope** (`claude plugin marketplace add haydenschmitty/floorplan --scope local`; `claude plugin install floorplan@floorplan --scope local`), verified against its `CHECKSUMS.txt`. Reviewed: no hooks, MCP servers, dependencies or install scripts; scripts run locally; its only network calls are the local `open.mjs` health probe and an opt-in waitlist that exists only when its local server runs. The upstream viewer is used **unmodified** (inside a sandboxed iframe) and exported with `serve.mjs --export` (no Ask bar). The published map file is served with `connect-src 'none'`, so Ask/waitlist cannot work by construction.
**Localization:** the upstream viewer has no Arabic support, so `portal/localization/` (`ar.json` dictionary + `adapter.js` + `adapter.css`) is injected into the exported map by `tools/localize_map.py` (the export's own hash-based CSP is extended by the hash of that one script only). It translates buttons, menus, tooltips, panels, the tour and glossary text, sets RTL on the chrome and keeps code/paths LTR. The graph canvas and all upstream behaviour are untouched. `browser_test.mjs` opens every menu and fails on any visible English string (`window.__FP_UNTRANSLATED`). New upstream strings after a plugin update show up there and are added to `ar.json`.
**Limits:** Ask is disabled (pre-written walkthroughs replace it); tests are not drawn on the map.

## Build locally (no server, no Docker)
```
python3 portal/tools/validate_content.py
python3 portal/tools/build_portal.py --sha $(git rev-parse HEAD) --out /tmp/portal --map /tmp/lawdesk-map.html
python3 -I -m unittest discover -s portal/tests -p 'test_*.py'
NODE_PATH=<dir with playwright-core> node portal/tests/browser_test.mjs /tmp/portal
```
`--audience public` omits file paths, line numbers and links to source (use only after owner approval).

## Publication (owner-approved only; operator with docker access)
Default: **private** — HTTP basic auth at the shared proxy, independent of LawDesk accounts. Public access needs an explicit owner decision (`FLOORPLAN_PUBLIC=yes` + a `--audience public` build).
1. **Deploy** (portal container only): `portal/deploy/scripts/deploy.sh <dist> <sha>-<n>` — builds image `lawdesk-floorplan-web:<release>`, creates the `--internal` network `floorplan-edge`, starts compose project `lawdesk-floorplan` (no published ports), waits for health, restores the previous release on failure.
2. **Credentials** (operator, never in git): `docker exec <proxy> caddy hash-password` → save the bcrypt hash to a mode-0600 file.
3. **Attach**: `FLOORPLAN_BASIC_USER=… FLOORPLAN_BASIC_HASH_FILE=… portal/deploy/proxy/attach.sh` — same pattern as `deploy/proxy/attach.sh`: backup, own marker block only, `caddy validate`, graceful reload (proxy never restarted), compares every other host's status before/after and restores automatically on any difference. Hostname `floorplan.167-86-90-174.sslip.io` (host IP and the LawDesk hostname were verified by DNS/HTTPS on 2026-11-27).
4. **Verify**: `portal/deploy/scripts/verify.sh floorplan.167-86-90-174.sslip.io <user>:<password-file>` — DNS, certificate, 401 without/with wrong credentials, Arabic RTL home, headers, POST refused, no dotfiles/API surface, LawDesk `/healthz` 200, Matbakhy hosts.
5. **Rollback**: `portal/deploy/scripts/rollback.sh` (previous image) · full removal: `portal/deploy/proxy/detach.sh`, `docker compose -p lawdesk-floorplan down`, `docker network rm floorplan-edge`.
Existing LawDesk and Matbakhy services are never touched; the proxy joins `floorplan-edge` only.

## Updating when develop changes
`portal/tools/refresh_portal.sh <develop sha>` (from a checkout of that sha): checks the sha is on develop, the plugin checksums, runs the incremental Floorplan refresh, **stops** if new/changed code lacks approved Arabic descriptions (a human writes and reviews them — no AI text is published unvalidated), validates all evidence at the new sha (a moved line breaks the build), builds, tests. Output is a complete release directory; deploying it is a separate, manual step. A gated CI workflow is deliberately **not** added yet (manual first publication; not every merge needs publishing).

## Security
Synthetic examples only; no secrets, env files, real case data or complaint content. Static nginx (unprivileged, read-only, caps dropped, 64 MB), GET/HEAD only, strict CSP (`script-src 'self'`, no inline styles), `noindex`, `no-referrer`, no API calls to LawDesk and no credentials of LawDesk anywhere. The sensitive internal architecture view is the `internal` audience only.
