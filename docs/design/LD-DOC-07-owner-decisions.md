# LD-DOC-07 — قرارات المالك (معتمدة)

الحالة: **معتمدة بتاريخ 2026-11-08**، بنص رسالة المالك التي اعتمدت حزمة التصميم (PR #65) وأذنت ببدء التنفيذ عبر حزم العمل والمراحل الثلاث.
أُلغيت قاعدة «اعتبار عدم الرد موافقة»؛ القرارات أدناه معتمدة صراحة، والتفاصيل التقنية الروتينية تُنفَّذ دون الرجوع للمالك.
حدود التفويض: التنفيذ والاختبار والدمج في `develop` والنشر التدريجي على UAT/Staging بعد كل حزمة ناجحة. **الإنتاج خارج التفويض.**

| # | القرار المعتمد | كيف يُنفَّذ |
|---|----------------|-------------|
| **D1** | ثلاثة أرقام منفصلة: رقم داخلي يولّده النظام، ورقم آلي قضائي يدخله المستخدم ويظل ثابتًا عبر الدرجات، ورقم قضية بالمحكمة مستقل لكل درجة | `reference_no` (النظام) و`automated_no` (المستخدم) على القضية، و`court_case_number/year` على الدرجة؛ لا يُشتق أحدها من الآخر |
| **D2** | فصل طبيعة النزاع عن المسار ودرجة التقاضي ونوع الإجراء | ثلاثة محاور مستقلة (LD-DOC-01 R7) |
| **D3** | الاطلاع: العضو المختص والبديل على المسندة إليهما؛ رئيس القسم على نطاق قسمه؛ مدير الإدارة القانونية على نطاق الإدارة؛ **صلاحية إدارة النظام وحدها لا تمنح الاطلاع على محتوى القضايا**؛ القضايا الحساسة تتطلب منحًا صريحًا؛ بقية الأدوار حسب الصلاحيات والنطاقات دون اطلاع شامل تلقائي؛ فصل صلاحيات الاطلاع والتعديل والاعتماد والتوزيع؛ التكليف بمهمة لا يمنح تعديلًا شاملًا | `CaseAccessPolicy` مركزية في الخادم تغطي القضايا والملفات والبحث والتقارير والتصدير والتقويم والمساعد |
| **D4** | الرقم المدني ورقم المنشأة هويتان متميزتان بحسب نوع الطرف؛ فصل صلاحية مشاهدة القيمة كاملة عن تعديل الطرف، مع إخفاء جزئي لغير المصرح لهم؛ لا تحقق قانوني غير موثق ولا إتلاف لبيانات قديمة غير مطابقة | حقل `civil_no` للأشخاص الطبيعيين و`establishment_no` للمنشآت؛ صلاحية `PARTY_ID_VIEW`؛ القيم القديمة تبقى كما هي |
| **D5** | خمسة مبالغ منفصلة بعملة KWD وثلاث منازل: الأثر المالي، المطالب به، المحكوم به، قيمة التسوية، الخسارة المحتملة | `numeric(15,3)` منفصلة، لا خلط ولا اشتقاق بينها |
| **D6** | المواعيد اليدوية المعتمدة مسموحة؛ لا احتساب قانوني آلي إلا بعد إدخال قواعد ومصادر وعطلات موثقة واعتماد المختص؛ لا اختراع مدد | `deadline_rule` و`official_holiday` فارغان؛ `calc_status` MANUAL/PROPOSED/APPROVED |
| **D7** | معالجة محلية مبدئيًا؛ التحقق من التشفير وحماية المفاتيح والنسخ والاستعادة قبل ترحيل الملفات؛ الحفاظ على كل المرفقات وروابطها؛ اختبار جودة البحث وOCR العربي بدل افتراض كفاية المحرك | WP5 |
| **D8** | تنفيذ المكونات والاسترجاع والاستشهاد والاختبارات؛ **لا مزود خارجي ولا إرسال بيانات قضايا إليه**؛ عند الحاجة يُعرض الخيار ويستمر العمل المستقل؛ مزود الاختبار ليس دليل اكتمال تشغيلي | WP10، التحقق التشغيلي «متعطل» |
| **D9** | تنفيذ سجل التدقيق وحمايته؛ لا حذف آلي للسجلات أو المستندات قبل اعتماد سياسة الاحتفاظ؛ انتظار السياسة لا يعطل بقية التنفيذ | لا مهمة حذف مجدولة |
| **D10** | قوائم قابلة للإدارة والتعديل مع التمييز بين قيم الوثيقة والمقترحة وحفظ التاريخ | `lookup_value.origin` (DOCUMENT/PROPOSED) مع تاريخ التعديل |
| **D11** | تنبيهات داخل النظام فقط؛ لا بريد ولا SMS ولا إرسال خارجي | `notification` داخلي |
| **D12** | نشر تدريجي على UAT/Staging بعد كل حزمة ناجحة مع استقرار البيئة | PR لكل حزمة؛ التحقق من SHA المنشور ورحلة فعلية |

## توجيهات تنفيذية مرافقة للاعتماد

- مراجعة التغطية معنويًا لا بمجرد تغطية أسطر الملف؛ الحفاظ على الأقسام الـ37 والمتطلبات والسيناريوهات.
- معالجة سبب 401 لحساب QA دون تعطيل المصادقة أو تغيير بيانات الدخول بصمت (التشخيص في `docs/evidence/DOC-WP0/qa-admin-401.md`).
- اختبار الـAPI القديم والجديد لتطابق التحقق والصلاحيات وغياب مسار يتجاوزهما.
- تطبيق نطاقات الاطلاع في الخادم: القضايا والملفات والبحث والتقارير والتصدير والمساعد.
- الحفاظ على البيانات الحالية واختبار الترحيل والنسخ والاستعادة.
- البقاء على المعمارية: Spring Boot وReact وSpring Security دون مزود هوية خارجي.
- لا يُعلن اكتمال المشروع مع وجود متطلبات متعطلة أو غير مختبرة؛ تُوضَّح ويستمر العمل في كل ما هو ممكن.

## ما لا يحتاج قرارًا (افتراضات منفذة)

KWD بثلاث خانات، توقيت الكويت للعرض، الأحداث UTC، التنبيهات داخلية، العربية RTL أساسية، أدوار قابلة للتعديل.
