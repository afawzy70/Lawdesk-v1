# LD-DOC-01 — تحليل الفجوات وسجل التوفيق مع الطلبات السابقة

الحالة: **مسوّدة للاعتماد** (لم يُعدَّل التطبيق). النسخة المفحوصة: `develop` عند `f32893e` (UAT يعيد نفس SHA).
المرجع التفصيلي ذرّيًا: `docs/requirements/lawdesk-comprehensive-requirements-matrix.md` (651 متطلبًا ذريًا بمعرّفاته، +38 معرّف قسم).

## 1. ما هو موجود فعلًا (من فحص المخطط والشيفرة)

الجداول (23 جدولًا): `legal_case`, `case_event`, `case_reference_counter`, `party`, `case_party`, `court`, `proceeding`, `judgment`,
`special_decision`, `hearing`, `expert`, `expert_referral`, `expert_session`, `task`, `case_document`(+`_content`,`_quota`),
`case_note`, مع `app_user`, `app_role`, `role_permission`, `user_role`, `audit_event`.
الصلاحيات: 28 صلاحية عامة (`CASE_*`, `PARTY_MANAGE`, `HEARING_*`, `DOCUMENT_*`, `TASK_*`, `REPORT_*`…) وثلاثة أدوار افتراضية.
التقييد حسب العضوية: تعديل القضية ومحتواها مقصور على المختص والبديل والمشرفين متى عُيّن مختص (LD-045)، أما الاطلاع فبصلاحية `CASE_VIEW` على كل القضايا.
الواجهة: قائمة القضايا، ملف القضية، التسجيل الحكومي، الدرجات والأحكام، الجلسات، الخبراء، المستندات (PDF)، المهام، اللوحة، 4 تقارير بتصدير، الإدارة والتدقيق، المحاكم.

## 2. الفجوات الكبرى (تفصيلها في السجل)

| المجال | الفجوة |
|--------|--------|
| الطلبات والأحكام | لا وحدة طلبات (القسم 5)؛ الحكم نتيجة واحدة وملخص فقط، لا منطوق ولا أسباب ولا مبالغ ولا نتيجة لكل طلب (9) |
| الدفوع والأدلة | غير موجودة (17، 20) |
| المكتبة | لا مكتبة أحكام ولا مبادئ ولا اقتراح سوابق (16) |
| الإدارات | لا هيكل قطاع/إدارة/قسم (6) ولا طلبات إفادة (18) |
| المخاطر والمواعيد القانونية | غير موجودة (19، 10)؛ لا قواعد مدد |
| الجلسات | بلا وقت وقاضٍ وحاضرين وسبب تأجيل وحالة «بلا موعد تالٍ» (7) |
| القضايا المرتبطة | غير موجودة (8) |
| الأرشيف | PDF فقط بحد عشرة ومخزّنة في قاعدة البيانات؛ لا Word ولا صور ولا OCR ولا إصدارات ولا تصنيف (13) |
| المذكرات والنماذج والتسويات والتكليفات | غير موجودة (12، 29، 23، 25) |
| التقويم والتنبيهات | تقويم جلسات ومهام جزئي؛ لا تقويم عام ولا كشف تعارض؛ لا مركز تنبيهات (15، 32) |
| الصلاحيات | 3 أدوار من 7؛ لا نطاق بالقطاع/الإدارة/القسم؛ الاطلاع على كل القضايا لكل صاحب `CASE_VIEW` (30) |
| البحث | فلاتر قائمة فقط؛ لا بحث موحد ولا نص المستندات (28) |
| المساعد | غير موجود، ومزود الذكاء الاصطناعي غير مصرّح (22) |

## 3. سجل التوفيق والتعارضات

| # | الطلب السابق (LD-045) | الوثيقة الجديدة | التوفيق المقترح |
|---|------------------------|------------------|-----------------|
| R1 | «الرقم القومي» يصبح «الرقم الآلي للطرف» بلا تحقق مدني | «الرقم المدني أو رقم المنشأة» وفق ضوابط السرية | **الوثيقة أحدث وتلغي التسمية السابقة.** الحقل `party.national_id` يُسمّى «الرقم المدني» للشخص و«رقم المنشأة» للمنظمة (حقل `registration_no` موجود). لا قاعدة 14 رقمًا؛ يُقبل نص حر مع تنسيق اختياري بعد اعتماد المالك (D4). القيم المخزنة لا تتغير. يضاف تصنيف سرية (D3). |
| R2 | رقم آلي للقضية يكتبه المستخدم وثابت عبر الدرجات، ورقم قضية لكل درجة | «رقم القضية الداخلي الآلي» | **ثلاثة معرّفات متمايزة** (D1): المرجع الداخلي الذي يولده النظام `reference_no` (LD-YYYY-NNNNN)، والرقم الآلي القضائي الذي يدخله المستخدم `automated_no`، ورقم القضية لكل درجة `court_case_number/year`. لا يُفترض أن الداخلي هو القضائي. التسمية المقترحة في الواجهة: «رقم القضية الداخلي» و«الرقم الآلي (قضائي)» و«رقم القضية بالمحكمة». |
| R3 | موقف الهيئة مدعٍ/مدعى عليه وأطراف متعددة | «صفة الجهة في الدعوى» + أطراف | يبقى كما نُفّذ ويُعتمد مصدرًا لـ«صفة الجهة». لا تغيير. |
| R4 | العضو المختص والبديل؛ تعديل مقصور عليهما والمشرفين؛ الاطلاع بلا تغيير | نظام صلاحيات مرن (القسم 30) ولا اطلاع شامل تلقائي | يتحول إلى **سياسة وصول مركزية** (نطاق + عضوية + منح) مع تفعيل افتراضي يحفظ السلوك الحالي إلى أن يعتمد المالك سياسة الاطلاع (D3). |
| R5 | إزالة «العمليات القانونية» من شاشة الإنشاء | وحدات الإجراءات والمواعيد والمهام مطلوبة | لا تعارض: الحذف لشاشة الإنشاء فقط (منفّذ). تبقى الوحدات في ملف القضية. |
| R6 | أثر مالي نعم/لا ومبلغ KWD | قيمة مطالب بها، حكم، تسوية، خسارة محتملة | **خمسة حقول متمايزة** لا حقل واحد: الأثر المالي المقدّر (LD-045)، القيمة المطالب بها `claimed_amount` على القضية، مبلغ الحكم لكل طلب/حكم، قيمة التسوية في التسوية، الخسارة المحتملة في إصدار تقييم المخاطر (D5). KWD بثلاث خانات عشرية قرار منتج. |
| R7 | استئناف/تمييز/تنفيذ | القسم 1 يعدّدها ضمن «نوع القضية»، والقسم 4 ضمن الدرجات | **ثلاثة محاور** (D2): طبيعة النزاع (إدارية/مدنية…)، المسار/الدرجة (أول درجة، استئناف، تمييز، دستورية، تنفيذ، تظلم)، ونوع الإجراء (صحيفة، طعن، تنفيذ…). تعرض «التظلم/الاستئناف/التمييز/التنفيذ» كمسارات لا كنوع نزاع. |
| R8 | الحد الأقصى لعشرة PDF لكل قضية (LD-026) | أرشيف متقدم بصيغ متعددة | يُرفع الحد ويُستبدل بحصة تخزين قابلة للإعداد بعد قرار D7. |
| R9 | `CASE_VIEW` يرى كل القضايا | عدم منح الاطلاع الشامل تلقائيًا | ينتقل إلى النطاقات (D3) بترحيل يحافظ على الوصول الحالي حتى القرار. |
| R10 | حالات المهمة: 4 | 7 | توسيع مع تحويل `OPEN→NEW`، `IN_PROGRESS` كما هي، `DONE→COMPLETED`؛ ترحيل بقيم معروفة وبلا فقد. |

## 4. ما لا يُخترع

لا مدد قانونية، ولا قواعد احتساب، ولا عطلات رسمية، ولا سياسة احتفاظ، ولا مزود ذكاء اصطناعي. تُنشأ الجداول والواجهات فارغة وقابلة للإعداد
ويظل التاريخ المحسوب «مقترحًا» غير معتمد إلى أن يعتمده عضو مختص (القسم 10). القوائم المعيارية غير المحددة في الوثيقة (نوع الحكم، صفة الحكم، أنواع المراسلات
الفرعية) تُنشأ كقوائم قابلة للتعديل بقيم ابتدائية مقترحة تُعلَّم «تحتاج اعتماد المالك».
