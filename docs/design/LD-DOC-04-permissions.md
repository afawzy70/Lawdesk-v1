# LD-DOC-04 — نموذج الصلاحيات والنطاقات (القسم 30)

الحالة: **للاعتماد**. التحقق دائمًا في الخادم عبر `CaseAccessPolicy` (خدمة واحدة تستعملها الشاشة والتقرير والتصدير والملفات والبحث والمساعد)، لا بإخفاء الأزرار.

## 1. الأدوار السبعة

| الدور | مفتاح | ملاحظة |

| مدير النظام | `ADMIN` | موجود |

## 4. النطاقات (من يرى أي قضية)

مستوى الرؤية = اتحاد: (أ) نطاق الدور/المستخدم `access_scope` (ALL، شجرة وحدة تنظيمية عبر `case_org_involvement`، أنواع نزاع، OWN)، (ب) عضوية القضية (مختص/بديل/مكلَّف بمهمة)، (ج) منح صريح `case_grant`.
القضايا ذات `confidentiality=RESTRICTED` تتطلب (ب) أو (ج) أو `CASE_VIEW_RESTRICTED`.

- **المُكلَّف بمهمة محدودة**: يرى القضية المكلف بها (عرض)، ويعدّل مهمته فقط (إكمال، سبب تأخير، تعليق)، ولا يعدّل القضية. هذا يحل A8 المعلّق من LD-045.
- **عدم الاطلاع الشامل**: بعد اعتماد D3 يُحوَّل `access_scope` الافتراضي من ALL إلى النطاق المعتمد. حتى ذلك الحين ALL محافظة على الحالي.
- **كل المسارات**: API القضايا والأطراف والوحدات الفرعية، تنزيل الملفات، التصدير، البحث (والمقتطفات)، التقويم، التنبيهات، اللوحة، المساعد؛ كلها تستدعي `CaseAccessPolicy` نفسها. اختبار يمرّ على كل controller ويفشل إن وُجد endpoint لا يستعملها.

## 5. التدقيق (القسم 31)

أحداث جديدة لكل ما في الوثيقة: تغيير المسؤول والبديل والمواعيد، الطلبات والدفوع والجلسات والأحكام والمستندات، الاعتماد، التصدير، استفسارات المساعد.
القيم السابقة والجديدة في `audit_event.details` (JSON)؛ الحقول الحساسة (رقم مدني، مبالغ تسوية) تُعرض لمن يملك `AUDIT_VIEW` ومعه نطاق القضية، وتُقنَّع لغيره. لا واجهة تعديل أو حذف.
