# Modern Chambers: visual review against approved Stitch

Approved source: [Google Stitch project 2890116183553293246](https://stitch.withgoogle.com/projects/2890116183553293246). Stitch MCP returned one saved screen, **LawDesk - Modern Chambers Dashboard**, ID `51490074816b4a16a0ebfbc19f35a506`, desktop 2560 × 2048. [Saved source screenshot](reference/stitch-dashboard.png). No approved report, mobile, or other route screens were saved in this project. The review below compares the actual render, not its prompt.

Browser renders use fictional, contract-shaped local responses; they do not prove UAT integration or independent QA. Compare [corrected English dashboard](screenshots/correction/dashboard-en-1366.png), [corrected Arabic dashboard at 375 px](screenshots/correction/dashboard-ar-375.png), [corrected English case inventory report](screenshots/correction/inventory-en-1366.png), and [corrected Arabic report at 375 px](screenshots/correction/inventory-ar-375.png). The original source is much wider than the 1366 px target and includes features absent from LawDesk v1.

| Stitch element | Current implementation | Visual result / remaining gap |
| --- | --- | --- |
| Charcoal rail, brass legal mark and active state | Dashboard-specific 104 px rail; responsive menu on phone | Rail width now matches the 1280 px Stitch composition. The app has more real modules, so its labels are smaller and its rail remains busier. |
| Ivory canvas, paper panels, fine rules and restrained brass | Shared design tokens and components | Consistent on dashboard, cases, operations, administration and reports. The live app uses simpler typography and less editorial contrast than the source. |
| Search in top bar | Permission-gated search of case reference/title to existing case list | Works with real API and URL state. The broader party/circuit search shown by Stitch has no corresponding v1 contract. |
| Horizontal operational signals | Four values from the real dashboard report | Thin tinted full-width strip and boxed counts follow Stitch more closely. Values and labels reflect existing backend fields; no fabricated pending submissions or trust accounts. |
| 5:7 Court Diary / Active Dossier first row | Live scheduled hearings and active case preview, permission-scoped | The corrected leading row uses stronger headings, a highlighted first hearing and a larger ruled dossier. A single real record still makes the diary shorter than Stitch's multi-record sample. |
| Rich dossier facts and evidence bundle | Existing case-party API supplies actual client/opponent names; matched calendar hearing supplies the next date | Where data exists, the lead case has a more faithful fact grid. The full legal record remains in case details. Counsel, claim value, POA, evidence bundle and milestone panels remain absent because the Dashboard cannot guarantee those facts. |
| Arabic legal language | Localized chrome and a fictional Arabic case title in the new sample | RTL order, reference isolation and text wrapping work at 320/375 px. The source mixes Arabic/English text in every panel; live records show the language stored by users. |
| Reports | No report screen exists in the approved Stitch project | The five real reports now share the Dashboard's pale heading band, ivory paper, brass summary rule, muted table heading, consistent filters, exports, pagination and empty states. This remains an interpretation. At 320 px the inventory's ten filters create a long first section; the data table is locally scrollable. |
| Mobile | No approved mobile source screen exists | Dashboard stacks diary and case register, signals stack at 320 px, menu and global search remain operable. This is a responsive interpretation. |

The source also depicts billing/trust accounting, print roll and a session folio. Those controls are absent from the implemented Phase 2–6 product and were not introduced as visual-only actions. The current report and case data remain tied to their existing APIs, permissions and workflows.

Automated checks on the corrected Dashboard at 320, 375, 768 and 1366 px in both languages reported no document-level horizontal overflow and no axe WCAG 2/2.1 A/AA violations. The same layout widths and languages were checked on all five report routes, with axe on the English desktop and Arabic mobile representative state of each. See [Dashboard matrix](screenshots/correction/dashboard-matrix.json) and [reports matrix](screenshots/correction/reports-matrix.json). These checks do not certify all screen-reader, keyboard, browser or UAT behavior.
