# LD-DOC-10 — عقود التكامل المستقبلي (القسم 34)

النص: «تصميم واجهات برمجية تسمح بالتكامل مستقبلًا مع أنظمة المراسلات والموارد البشرية والأرشفة والبريد الإلكتروني والأنظمة الحكومية ذات الصلة، وفق الموافقات اللازمة».

الحالة: **لا اتصال ولا بيانات دخول ولا عناوين.** كل محوّل `DisabledIntegrationAdapter` يرفض أي استدعاء برمز `INTEGRATION_DISABLED` (422). لا إعداد ولا جدول ولا واجهة يمكنها تفعيله؛ التفعيل قرار مالك منفصل لكل نظام مع اتفاقية مشاركة البيانات وإدارة الأسرار.
الواجهة `GET /api/v1/integrations` (صلاحية `USER_VIEW`) تعرض المحوّلات وحالتها فقط. العقد المفصل في `integration-contracts.openapi.yaml` (وثيقة، لا تُخدَم من التطبيق).

| الرمز | النظام | الاتجاه | العمليات المعرّفة في العقد |
|-------|--------|---------|----------------------------|
| `CORRESPONDENCE` | نظام المراسلات | وارد وصادر | `registerIncomingLetter`, `registerOutgoingLetter`, `getLetterStatus` |
| `HUMAN_RESOURCES` | الموارد البشرية | وارد | `getEmployee`, `listOrganisationUnits` |
| `ARCHIVING` | الأرشفة | صادر | `transferDocument`, `getTransferStatus` |
| `EMAIL` | البريد الإلكتروني | وارد فقط | `listReceivedMessages`, `getReceivedMessage` |
| `GOVERNMENT_SYSTEMS` | الأنظمة الحكومية ذات الصلة | وارد وصادر | `lookupCaseStatus`, `submitFiling` |

## شروط عامة لأي تفعيل مستقبلي

1. موافقة المالك الصريحة على النظام والبيانات المتبادلة (لا بيانات قضايا خارج النظام دون ذلك — قرار D8 ونصيرته للتكامل).
2. البريد: لا إرسال صادر (القرار D11: تنبيهات داخل النظام فقط)؛ العقد وارد فقط حتى قرار جديد.
3. كل نداء داخل الحدود يمر بـ`CaseAccessPolicy`؛ المحوّل لا يقرأ قضية لا يراها المستخدم الذي بدأ الطلب.
4. بيانات الدخول من مخزن الأسرار فقط؛ لا تُخزَّن في المستودع أو الإعدادات العامة أو قاعدة البيانات.
5. كل نداء يُسجَّل في سجل التدقيق (المعرّف والنتيجة، لا المحتوى الحساس).
6. اختبار تكامل بنظام تجريبي للجهة قبل أي استعمال، وإيقاف فوري عبر إلغاء الاعتماد.
