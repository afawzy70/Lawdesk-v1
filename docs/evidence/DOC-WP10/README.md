# DOC-WP10 — المساعد القانوني (LD-059): المكونات والاسترجاع والاستشهاد، دون مزود

**الحالة: وضع اختبار غير تشغيلي. لا مزود ذكاء اصطناعي معتمد (القرار D8) ولا بيانات قضايا تخرج من النظام.**
التطبيق يعلن `operational: false` و`reason: NO_APPROVED_PROVIDER` في الواجهة البرمجية وفي صفحة الحالة (`/assistant`: «غير مفعّل: لا مزود معتمد») وفي لافتة لوحة القضية.
**مزود الاختبار المحلي `LOCAL_EXTRACTIVE_TEST` ليس دليل اكتمال تشغيلي.** يقتبس مقاطع مسترجعة حرفيًا ولا يولّد نصًا ولا يستعمل الشبكة؛ يثبت المكونات (الاسترجاع، الاستشهاد، الرفض، الاطلاع، التسجيل) لا جودة الصياغة القانونية.

## ما لم يُنفَّذ أو متعطل

- **التحقق التشغيلي: متعطل (BLOCKED)** حتى يعتمد المالك مزودًا (LD-DOC-09). لا اختبار جودة صياغة عربية قانونية ولا دقة ولا أداء لنموذج لغوي.
- تلخيص/تحليل/صياغة **مولَّدة** (إعادة صياغة، استخلاص دلالي، «ما الطلبات التي رُفضت؟»، «الدفوع التي لم يُفصل فيها») تحتاج مزودًا؛ المبني اقتباسي فقط.
- تصنيف المستندات تلقائيًا وتحديد **المستندات الناقصة** (22.2 و«ما المستندات الناقصة؟»): يحتاج تعريف المالك لمجموعة المستندات المطلوبة؛ لم يُخترع.
- تمييز الأحكام **المؤيدة** من **المخالفة** آليًا (22.3): يُعرض فقط الاتجاه الذي سجّله العضو في المكتبة.
- مقارنة حكم الكلية بحكم الاستئناف وطلبات الخصوم بالمنطوق: المقارنة الحالية بين مستندين نصيًا فقط.
- رقم الصفحة: غير متاح لأن النص المستخرج لا يحفظ حدود الصفحات (يُعرض عدد الصفحات الكلي فقط).
- لا سياسة احتفاظ لسجل الاستفسارات (D9)؛ لا حذف آلي.
- عند اعتماد مزود لاحقًا: يُكتب محوّل في حزمة منفصلة ويُحدَّث `AssistantBoundariesTest` عن قصد.
