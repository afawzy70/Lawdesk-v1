# Contributing to LawDesk v1

These rules are enforced by `tools/repo_policy.py` (locally through the git hooks below, and in CI from LD-005).
If you change a rule, change the script and its tests in the same pull request.

## Repository layout

| Path | Contents |
|------|----------|
| `backend/` | Java 21 / Spring Boot API (from LD-002) |
| `frontend/` | React + TypeScript web app (from LD-003) |
| `deploy/` | Docker Compose staging stack, proxy snippet, deploy and rollback scripts (LD-006) |
| `tools/` | Repository tooling and its tests |
| `.github/` | CI workflows, PR template, code owners |
| `product/`, `qa/`, `architecture/`, `operations/` | Approved product and QA baseline (owned by product/QA) |
| `docs/delivery/` | Phase checkpoints and refined acceptance criteria |
| `docs/governance/` | Owner-approved delivery strategy (priorities, Phase 7 deferral, security, performance, release gates, delivery states) |
| `docs/evidence/<story>/` | RED/GREEN/REFACTOR logs for each story |

## Branches

- `main` is stable and only receives `release/*` and `hotfix/*` pull requests.
- `develop` is the integration branch. Successful merges deploy to staging once LD-006 is approved.
- Work happens on `feature/*`, `fix/*`, `docs/*`, `qa/*` or `chore/*` branches, opened against `develop`.
  Include the story ID when there is one: `feature/LD-002-backend-bootstrap`.
- Nobody commits directly to `main` or `develop`.
- Implementation (Claude) and independent QA (Codex) use separate worktrees and separate pull requests.

## Commits

Conventional Commits, subject at most 72 characters, story ID in the scope:

```
feat(LD-002): add liveness and readiness endpoints
test(LD-004): cover failed migration rollback
```

Types: `feat fix docs test refactor chore ci build perf style revert`. Merge and revert commits generated by git or GitHub are accepted as-is.

## Test-driven development

Every story follows RED → GREEN → REFACTOR:

1. Write the failing test first and save its output to `docs/evidence/<story>/NN-red*.log`.
2. Implement the minimum to pass and save `NN-green*.log`.
3. Refactor, re-run the story's tests and the regression suite, and save `NN-refactor*.log`.

Each log starts with the command and UTC timestamp. Never mark a skipped or unexecuted test as passed.

## Pull requests

- Follow the owner-approved [delivery strategy](docs/governance/LAWDESK-DELIVERY-STRATEGY.md): priorities, delivery
  states (IMPLEMENTED, INTEGRATED, DEPLOYED, QA ACCEPTED, PRODUCTION READY) and the testing rules for the shared host.
- Target `develop`; fill in `.github/pull_request_template.md` (story IDs, QA case IDs, commands and results).
- The author never approves or merges their own pull request; independent QA review is required.
- Do not bypass failing checks. If a check is wrong, fix it in a separate reviewed change.

## Local setup

```bash
git config core.hooksPath .githooks   # enables branch and commit-message checks
python3 -I -m unittest discover -s tools/tests
```

## Secrets

Never commit credentials, `.env` files or keys. Configuration comes from environment variables; examples live in `*.env.example` files with placeholder values only.
